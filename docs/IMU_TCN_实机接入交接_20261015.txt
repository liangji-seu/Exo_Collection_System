三、已确定的模型契约
优先加载 final_model.ts；scaler 已内嵌，禁止再归一化一次或重复恢复输出尺度。
输入 float32 [B,40,12]，BTC 布局，20 Hz 网格、40 帧、历史跨度 1.95 s。
严格通道顺序：right_leg_acc_x/y/z，right_leg_gyr_x/y/z，pelvis_acc_x/y/z，pelvis_gyr_x/y/z。
单位：加速度 m/s²，陀螺仪 rad/s；使用训练时的原始物理传感器轴，不自行旋转、去重力、添加静态校准或滤波。
两枚 IMU 的物理身份、佩戴部位、坐标轴和设备 ID 必须在预检中明确；不得依赖设备枚举顺序猜测。
已有 xsens_mtw_usb.py 的 descriptor 包含 device_ids/slot/物理映射状态；独立USB模式标注 cross_device_hardware_sync_verified=False、alignment_mode=none_independent_streams，事件为主机到达时间且 device_timestamp=None。因此应保留双设备独立时间序列，并明确区分主机到达年龄与真实设备采样年龄；不能把当前数据通路宣称为已硬同步或已测出真实端到端延迟。
参照部署包 predict.py 的 OnlineCausalPredictor：每个网格点仅取此前最近样本；任一设备相对该网格点的样本年龄超过 50 ms、数据非有限值、缺少历史或缺帧则拒绝/预热，不补零，不复制首帧凑足历史。
在线网格由单调时钟推进；相同网格终点只能接受一次预测。检查独立的传感器采样/接收时刻，不能用新一轮推理的时间掩盖旧数据。
输出单一当前右髋屈伸净关节力矩 Nm/kg。标签为 hip_flexion_r_moment / subject.mass_kg；只在中层乘一次被试体重 kg。

四、接口与三层控制方案
顶层：提供命名明确的 right_hip_moment_nm_per_kg、源网格时间和输入有效性，保持估计量与辅助指令分离。
中层：对估计值做可配置因果低通、体重及助力比例缩放、非负时间延迟和电机方向映射。
右侧期望值可表示为：desired_right_nm = right_sign × mass_kg × assist_gain × delay(causal_lowpass(predicted_nm_per_kg))。
滤波必须使用真实步长/固定有效网格，不能使用需要未来样本的 filtfilt。附加延迟用按时间管理的缓冲区，不用 sleep 阻塞接收或界面；展示额外设置延迟，不能把它称为总系统延迟。
停止、故障、换模型、变更质量/比例/方向/延迟后清理滤波与延迟历史；重新预热，避免旧非零指令延后释放。
用户已测定：左电机正 Nm 向后助力；右电机正 Nm 向前助力。只有确认训练输出正号对应右髋前屈，right_sign 才设 +1，否则经验证显式设 -1。
本模型只估计右髋；本次左电机命令固定为 0，不镜像右侧估计。仍显示双侧位置、速度和反馈力矩。

底层：从用户给定脚本抽取无 GUI 的力矩服务，接入 TorqueOutput；保留 Mock 后端。不要把 tkinter 窗口嵌入 Qt，也不要在测试中实例化会自动使能的原 GUI。
协议：串口 1,000,000 baud；控制帧头 0xAA，payload <H3f（seq、左Nm、右Nm、limit），CRC8 poly 0x07 init 0，尾 0x55；使能/失能帧头 0xBB，命令 0xFC/0xFD；反馈 <BHBBffffffIBB，共35字节，含 seq/state/err、双侧pos/vel/torque及设备时间。
一个服务独占同一个电机 COM 口，并向界面/订阅端发布反馈；避免 encoder adapter 再次打开该端口。收发分离但所有写入串行化，处理半帧、粘帧、CRC错误和重新同步。
现有 adapters/encoder/teensy_serial.py 已能解析相同35字节反馈，当前只读，可复用解析器；不要让它和新服务各开一个串口。硬件项目 protocol.md 描述另一套 AA LEN TYPE 协议，不能混用；本次按已验证脚本及 ExoCode.ino 的实际实现。
底层可按现有200 Hz发送最新有效命令；命令有效期独立于重发周期。重复发送旧命令不能刷新其有效期。

五、必须实现的底层限幅与故障行为
用户明确要求：中层即使给出超过阈值的值，底层最多发送该阈值。对正负两方向都执行：sent_nm = clip(desired_nm, -limit_nm, +limit_nm)。
限幅必须位于底层服务每次实际组帧/写串口之前，覆盖所有命令入口；不只依赖中层、UI滑块或固件收到的 limit 字段。帧中的 limit 也必须合法。
初始代码的上位机全局上限为9 Nm、GUI初值为5 Nm。2026-10-15后续按用户要求调整：在线界面允许自行设置0–18 Nm，采用ExoCode.ino源码定义的±18 Nm协议范围，所有层共用domain/motor_protocol.py常量；不改动或自动刷入固件。当前在线界面未配置时阈值为0，已缓存值不会自动提高。这些实现值不代表本次人体试验已认可的安全阈值，实际限值由操作者设置；每帧按所设阈值限幅，模型配置不能突破协议上界。
阈值必须有限且非负；负数/NaN/Inf/无法解析时拒绝使能并归零。期望力矩 NaN/Inf 归零并报告故障。降低阈值必须对正在发送的旧命令立即生效，不等下一次推理。
底层独立检查命令年龄、反馈年龄和反馈 state/err；异常时归零并失能、锁存故障。反馈缺失时显示过期，不能继续把旧位置显示成有效状态。
急停、断开、关窗、换模型、推理异常、IMU过期均使输出归零且禁止自动恢复。重新使能需要操作者动作和预检通过。
不要保留原脚本“连接后3秒自动使能”的行为。写入使能帧成功不等于电机反馈已确认使能，界面应区分。
使用统一锁/状态代号防止正在进行的旧推理覆盖急停后的零值；热重载须确认旧推理和发送线程已停止。当前 _stop_controller 忽略 stop_and_wait 的失败，需要修正。
断连后主机不能保证零帧送达，需确认既有固件掉线保护；本阶段不要擅自刷固件。这里的限幅保证发送指令受限，不等同于实际测得力矩绝无动态超调。
已读到的 ExoCode.ino 源码有250 ms控制帧超时自动失能和下发CAN前限幅（约212-217、245-253行）；需现场确认设备实际刷入版本与此源码一致，不把源码检查当作实机验证。

实时显示：当前输入模态与各设备状态/采样率/数据年龄、12通道预览、右髋估计Nm/kg及换算Nm、期望辅助Nm、底层限幅后发送Nm、限幅标志、双电机pos(rad)/vel(rad/s)/反馈Nm、使能/故障状态。
若本机推理/调度达不到20 Hz或输入年龄要求，展示失败原因并保持零输出，不暗中放宽模型契约。
本次运行日志记录模型哈希、设备映射、体重、助力参数、阈值、时间戳、估计、期望、限幅指令、反馈和故障。
