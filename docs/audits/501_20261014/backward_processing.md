用户确认倒走时身体转身 180°，跑带方向不变。身体朝向、行走类别和关节力矩符号分别处理。不能通过取反水平原始力或全部关节力矩实现倒走支持。

## 实现

- `pipeline/opensim_io/walking_direction.py`：双脚 Heel→Toe 判断身体朝向，正向轻微 yaw 保持原样，背向才用 `diag(-1,1,-1)` 绕 ground 竖直 Y 轴做常量 180° proper rotation。每脚至少 30 个有效帧、方向余弦绝对值 >0.7 且朝向一致率 ≥90%；倒走不确定或含转身的窗口拒绝。
- `prep_session.py`：静态与动态分别记录旋转。先按实验室标定/真实坡度处理 force/COP，再将动态 marker、force、COP、free torque 同时旋转。关节力矩保持 OpenSim 解剖坐标符号。viewer 读取同一 TRC/MOT，并保存方向策略元数据。
- 双脚映射由原生 R/L 在单支撑期间的 COP 到解剖双脚 Heel–Toe 水平线段距离决定，比较保持/交换，不由工况名称直接假定。每原生侧 ≥3 段、每段 ≥5 帧、所选脚距离中位数 <150 mm、至少80%段领先 >20 mm、按完整接触段 bootstrap 的优势95%区间下界 >20 mm，且两侧决定一致，否则拒绝。阈值属于工程质量门槛，尚非经过独立验证的测量精度。
- `run_process.py` 批量入口与 `run_calculate.py` 单条入口共用策略。`STAND_BWALK_STAND` 不再默认丢掉起停后只截稳态，需在 Calculate 明确设置固定身体朝向的分析窗口；批量遇到该试次提示跳过并转单条审核。
- **2026-10-15 支持边界更正：** 手填分析窗口仅解除自动截取稳态的限制，不代表完整“静止→倒走→静止”已经支持可靠的力矩真值。当前混合记录中缺失的原生左右分力会被置零；`support_mask` 用于摘要和质量评估，没有自动屏蔽 viewer 或 CSV 中这些帧的力矩。因此不能把缺少双侧分力的静止段当作有效真值，完整工况仍需补齐阶段识别、静止期载荷处理与导出有效性策略。手动分析窗口应使用动态 C3D 从 0 s 开始的时间，且与静态标定文件的“静态稳定窗口”分开设置。
- Gaitway 的左右分力标记为厂商算法分解，非分别独立实测。倒走即使几何门槛通过，QC 仍至少 WARN，CSV QC 附带文件/界面保持 WARN。旧倒走 CSV 缺少当前策略和映射证据时显示需重算，旧历史标记失效并禁止直接再导出；原文件不删除。
- Fz 起点仅解释为接触起始，不能因倒走命名为足跟先着地。此路径不使用旧 C3D 单支撑力分配或旧 Heel/Toe 最低点事件器。
